# Gripper UX Audit — 2026-04-28

Audit grounded in current code + research on Tindeq Progressor, Crimpd, Frez, Tension Board, and Material Design bottom-navigation guidance.

Severity scale: **P0** ship-blocker for a polished v1, **P1** strong polish, **P2** nice-to-have, **P3** nitpick.

---

## Architecture / Navigation

### A1 — 6 bottom-nav tabs exceed Material limit (P0)
- Material Design bottom navigation guidance: 3-5 destinations.
- Tindeq sticks to 5 tabs (Home, Sessions, Programs, Competition, Profile).
- Gripper has 6: Live, Train, Presets, Party, History, Settings.
- Even with `softWrap = false`, 6 labels at 11sp on a 6.4" device produce 8-9dp/char which only barely fits and looks cramped (Image #4 confirms).
- **Fix options:** (a) Merge Presets into Train via a top toggle "Built-in / Custom"; (b) move Settings to a top-bar icon overflow; (c) move Party to a Live-tab quick-action FAB instead of a tab.
- Recommendation: merge Presets into Train (top toggle/tab), keep Party as a 5th nav item, demote Settings to top-bar icon. Net 4-5 tabs.

### A2 — Tab label "Train" vs "Presets" overlap conceptually (P1)
- Train = built-in programs, Presets = custom rep configs. New users will not know which to enter.
- Tindeq uses one "Programs" tab with built-in + custom tabs inside.
- **Fix:** consolidate (see A1).

### A3 — No top-level app branding / version visibility (P3)
- About card buried in Settings shows "Gripper · POC" + sample-rate caveat but no semver / build number.
- **Fix:** wire `BuildConfig.VERSION_NAME` into about row.

## Connection & Setup

### B1 — Connection strip persists at top, eats vertical space (P1)
- `ConnectionStrip` is rendered above every tab via `AppRoot`. When scanning fine + receiving data, it still occupies ~48dp.
- Tindeq pattern: connection state appears only while NOT connected, then collapses or moves to a small dot in nav.
- **Fix:** when `state == SCANNING` and Hz > 1.0 for 3 s, collapse strip into a small inline indicator (current `StableIndicator` already shows Hz). Otherwise remain visible.

### B2 — No first-launch onboarding for device pairing (P1)
- App requests permissions (Toast on denial) and routes to `LiveScreen`. New user sees empty gauge + "Idle" with no narrative.
- Tindeq pattern: account → device scan → first session. Crimpd: timer-first with intro.
- **Fix:** add `OnboardingScreen` shown when `mvc == 0 && sessions == empty`: 3 panels — (1) power on WH-C06, (2) tap Scan, (3) pull max → save MVC. Then route to Live.

### B3 — Permission denial = ephemeral Toast (P1)
- `MainActivity:33` shows a Toast pointing to Settings. Toast disappears in seconds; user can't recover without remembering the path.
- **Fix:** swap Toast → persistent in-screen banner (top of Live) with "Open Settings" button until perms granted.

### B4 — No auto-reconnect on transient BLE drop (P2)
- `BleScanner.State.IDLE` state requires manual user re-tap of Scan button.
- Tindeq auto-resumes scan when device disappears mid-session.
- **Fix:** if scan was running and connection drops, keep the scanner in SCANNING for ~30 s (already handled by BLE adv interval) and surface "Reconnecting…" inline.

## Live Screen

### C1 — Tare and Reset Peak share visual weight = ambiguous primary action (P1)
- Two outlined buttons side-by-side, identical chrome. Newbies don't know which is the destructive one.
- Tindeq pattern: utility row uses icon-only secondary buttons, with one primary action elsewhere.
- **Fix:** make "Tare" the primary tonal button (most common reset), demote "Reset Peak" to icon-only or move into the chart card overflow.

### C2 — Grip selector never resets / never warns (P1)
- `GripSelector` chip stays at last value across launches. If user sets MVC under "half crimp" and then pulls "open hand" without changing it, history misattributes the grip.
- **Fix:** show grip name in the MVC card subtitle ("MVC (left, half crimp): 28.0 kg"). Optionally prompt "Grip: half crimp — confirm?" on first pull of session.

### C3 — Stable indicator clutter (Stable/Settling + Hz + dot) on a single right-aligned column (P2)
- Three pieces of metadata stacked at far right competes with grip chip on left and chart in middle.
- **Fix:** drop the dot or drop "Settling" wording, replace with "Hz · stable" / "Hz · noisy". Single line.

### C4 — Stats grid (Peak / Avg10s / In Zone) shown even with no MVC set (P2)
- "In Zone" is meaningless until `targetKg > 0`. Peak / Avg are useful but the In Zone cell shows "0.0 s" misleadingly.
- **Fix:** hide In Zone cell when `targetKg == 0` and re-flow to 2 cells.

### C5 — MVC comparison + Save MVC live in one tall card (P2)
- MvcComparisonCard combines cells + Save button. On small phones the card pushes the Tare/Reset row off-screen. Confirmed in screenshot Image #4 where Tare/Reset are very low.
- **Fix:** convert Live into a `verticalScroll` column OR move MvcComparisonCard to a collapsible "Per-hand" section that opens via a "MVC ⌃" header tap.

### C6 — No quick toggle for Voice/Haptic feedback (P3)
- These are key during a pull but buried in Settings.
- **Fix:** add a small icon toggle row above the action bar — speaker icon + buzz icon, tap to toggle.

## Session Screen

### D1 — Phase color convention inverted vs climbing norm (P1)
- Code: work = green, rest = orange, pre-roll = blue.
- Climbing convention (Tindeq, Crimpd, Tension): work = orange/red (intensity), rest = green/blue (calm), pre-roll = gray/blue (neutral).
- Green-during-work makes the screen feel "go!" but conflicts with target-zone "in zone = green" semantics already used in `ForceGauge` (green fill when in target zone).
- **Fix:** swap to work = `0xFFFF6B35` (existing accent), rest = `0xFF34C759` (calm green). Pre-roll stays blue.

### D2 — Action bar mixes 3 buttons during run (Pause/Skip/Stop) (P2)
- All tonal/outlined, weight 1f each. Stop is destructive but only differentiated by error tint — easy to mis-tap on small screens.
- Tindeq pattern: large central Pause/Resume + smaller icon Stop.
- **Fix:** primary is Pause/Resume full-width when running; Skip + Stop as smaller icon buttons in a row above.

### D3 — No "skip to next set" vs "skip to next phase" distinction (P2)
- `vm.skipPhase()` jumps current phase. Long rests cannot be skipped to start of next set in one tap.
- **Fix:** add a long-press on Skip → "Skip set" menu.

### D4 — Pre-roll says "GET READY" with `letterSpacing = 4.sp` — visually loud (P3)
- Works visually but blocks numeric countdown for >1 s, reducing the "3-2-1" feel.
- **Fix:** smaller "GET READY" subtitle, keep big numeric countdown unobstructed.

### D5 — Skipping a phase doesn't store partial samples to RepRecord (P2)
- Code-only, surfaces as: skipped reps appear in History as 0 kg peak. Confusing in trend chart.
- **Fix:** mark skipped reps with a flag, hide them from trend, label as "skipped".

## History Screen

### E1 — Long stack of cards: Hand-comparison, MVC progress, per-program trends, sessions list, all in one LazyColumn (P1)
- Scrolling 50+ sessions makes hand/MVC summary scroll out of view.
- Crimpd uses a top filter row.
- **Fix:** add a sticky `ScrollableTabRow`: All / Programs / Per-hand / MVC. Default = All (compact summary cards on top), tabs filter the list.

### E2 — TrendCard collapses flat when peaks are equal (audit P3 already noted, fix one liner)

### E3 — No export / share session (P2)
- No way to pull data out for spreadsheet analysis.
- **Fix:** SessionDetailScreen → Share button → CSV via `Intent.ACTION_SEND`.

### E4 — Clear All wipes both sessions and MVC records — silent (P1)
- Confirmation dialog mentions "all sessions" but `clearHistory()` also wipes `mvc_records`. User who intends to start fresh sessions loses MVC trend.
- **Fix:** offer 2 separate buttons: "Clear sessions" + "Clear MVC records". Or expand the dialog text to mention both.

## Party Screen

### F1 — Capture flow has manual peak reset between players (P1)
- After "Save Peak" the modal closes but `_peakKg` retains the saved value, so next player must remember to tap Reset Peak. Easy to forget → next player attributed prior pull.
- **Fix:** auto call `vm.resetPeak()` after `partyCapturePeak` succeeds. Surface a snackbar "Saved 28.0 kg to Alice (Left). Pull next."

### F2 — No leaderboard celebration / sound (P3)
- Party mode is for joking around — adding confetti / haptic + voice "new leader!" on rank change makes it more fun.
- **Fix:** detect rank change in vm, fire `coach.cheer()` + small confetti animation.

### F3 — Player avatar = first letter only is bland (P3)
- **Fix:** generate deterministic avatar color from name hash; show next to rank medal.

## Settings

### G1 — Slider for target % MVC has no haptic snap to 5%/10% (P2)
- Range 10..120 in 1% steps. Hard to dial in 70 vs 75.
- **Fix:** `steps = 21` for 5% increments + numeric edit field.

### G2 — No units toggle (kg / lb) (P1)
- Climbing community split: NA mostly lb, EU/UK kg. Hard-coded `%.1f kg` everywhere.
- **Fix:** add `units` enum to Prefs; centralize formatter; toggle in Settings → Display.

### G3 — Calibration not surfaced (P2)
- WH-C06 has factory calibration. App has Tare on Live but no "Calibrate at known weight" wizard.
- **Fix:** Settings → Device → "Calibration check" routine: hang known weight, app shows offset.

### G4 — Coaching toggles are simple switches without sample (P3)
- **Fix:** "Test voice" and "Test haptic" buttons.

## Iconography & Visual Polish

### H1 — Bottom nav is labels-only, no icons (P1)
- Tindeq + Crimpd both use icons + labels. Icons aid recognition speed.
- **Fix:** add Material icons per tab: Live = `Bolt`, Train = `FitnessCenter`, Presets = `Tune`, Party = `Groups`, History = `History`, Settings = `Settings`.

### H2 — Theme uses `Material.NoActionBar` parent (legacy) and dark-only (P2)
- Light theme defined in `Theme.kt` but never selectable in Settings.
- **Fix:** add Settings → Display → "Theme: System / Light / Dark".

### H3 — No system bar contrast tuning when light theme active (P3)
- Currently transparent status bar with white window bg in light = invisible icons (already fixed by switching parent to dark Material). On future light support, need `WindowCompat.getInsetsController(window).isAppearanceLightStatusBars = true`.

## Accessibility

### I1 — `contentDescription = null` on all decorative icons (acceptable) but force readout `Text` not labeled for TalkBack (P2)
- Talkback users hear "0.0 kg" but no context that this is the current force.
- **Fix:** wrap force readout in `Modifier.semantics { contentDescription = "Current force, $kg kilograms" }`.

### I2 — Touch targets on small chips (StableIndicator dot, ConnectionStrip Scan button) below 48dp (P2)
- Scan button is `OutlinedButton` so OK. Chip text "L"/"B"/"R" in MvcComparisonCard cells likely < 48dp tall on phones. Confirmed in screenshot.
- **Fix:** ensure cells `Modifier.heightIn(min = 48.dp)`.

### I3 — Color-only signal for asymmetry severity (green/orange/red) (P2)
- Color-blind users miss the severity.
- **Fix:** prepend an icon: ✓ <5%, ⚠ 5-10%, ⚠⚠ ≥10%.
